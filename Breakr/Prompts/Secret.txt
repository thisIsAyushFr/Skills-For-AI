AGENT: SecretBreaker
Detects: provider keys (AWS, GitHub, Stripe, OpenAI, Anthropic, Slack,
SendGrid, Twilio, Google), private keys, database URLs with passwords,
generic "password/secret/token = '...'" assignments, and .env files that
.gitignore does not cover. Evidence is masked (first 4 chars + ***).

HOW TO VERIFY
1. Is it a real credential?
   - Provider-format keys (sk_live_, ghp_, AKIA..., -----BEGIN PRIVATE KEY)
     are almost always real. Treat as CONFIRMED unless clearly a doc sample.
   - Generic matches: check whether the value is a placeholder, a UI label,
     a test value, an enum ("password" field name), or a public identifier.
2. Where does it end up?
   - In frontend code (React/Vue/Svelte components, NEXT_PUBLIC_/VITE_ vars,
     anything under public/) it ships to every visitor: raise severity.
   - In server code it is still exposed to anyone with repo access, CI logs,
     and the git history forever.
3. Is the file tracked by git? Run: git ls-files <file> and
   git log --oneline -- <file>. If it was EVER committed, the secret is in
   history even if deleted now.
4. Google "AIza" keys and Firebase web config apiKey values are public by
   design. Only report them if the key is unrestricted or used for paid APIs.
5. Stripe sk_test_ keys: LOW. pk_live_/pk_test_ (publishable): not a finding.

FALSE POSITIVES TO DISMISS
- Values like "your-api-key", "<token>", "changeme" in .env.example / docs.
- Test fixtures with obviously fake keys (but say so).
- Hashes, nonces or checksums that merely live in a variable named token.

FIX
1. ROTATE the credential first. Removing it from code does not un-leak it.
2. Move it to an environment variable / secret manager:
     Node:   const key = process.env.STRIPE_SECRET_KEY
     Python: key = os.environ["STRIPE_SECRET_KEY"]
3. Add .env and .env.* to .gitignore; commit a .env.example with dummy values.
4. If it was committed: purge history (git filter-repo or BFG) AND rotate.
5. Add a pre-commit secret scanner (gitleaks, trufflehog) to stop repeats.
